## New bugs

### BUG-8: Body faces 180 degrees wrong direction for WASD movement

**Severity**: High (confusing UX)

When pressing W (forward), the body walks backward relative to the direction its face points. The STL coordinate frame has the body facing the opposite direction from the movement vector. Not "like a videogame" as users would expect.

**Evidence**: Pressing W at 60 dBm caused distance to increase from ~10 m to 11.5 m (body walked away from antenna instead of toward it). Front camera view confirmed body faces toward the camera while moving away.

**Fix**: Rotate the body mesh 180 degrees around Y in the movement code, or negate the forward vector in the WASD handler.

---

### BUG-9: Voxel RT with reflections crashes server (OOM)

**Severity**: High (data loss, server crash)

RT order 1 on the voxel scene (21,448 voxels, ~250K triangles for the RT mesh) consumed 100% RAM (16 GB) and killed the Python process. No timeout, no progress indicator, no way to cancel.

**Observed**: Server process used 35% CPU and 100% RAM for several minutes before being killed. Browser became unresponsive. Server had to be manually restarted.

**Fix options**:
- Add a triangle count check before launching RT. Warn/block if mesh exceeds a threshold (e.g., 50K triangles).
- Add a timeout to the RT computation (e.g., 60 seconds).
- Add a cancel endpoint and button.
- Add RT progress indicator showing estimated completion.
- Investigate DiffeRT JAX GPU support for acceleration.

---

### BUG-10: WASD keys require prior canvas click (no focus hint)

**Severity**: Medium

Key events don't reach the WASD handler if the user hasn't clicked the 3D canvas first. Pressing W/A/S/D does nothing until the canvas has focus. No visual hint tells the user what's wrong.

**Evidence**: Five W key presses had zero effect. After clicking the canvas, holding W immediately moved the body.

**Fix**: Add a visual cue (e.g., pulsing border, tooltip "Click scene to enable controls") when key presses are detected but canvas doesn't have focus.

---

### BUG-11: Distance label vs dashboard mismatch

**Severity**: Medium

The floating distance sprite label showed "2.3 m" while the dashboard showed "Distance: 8.3 m" after RT computation placed the antenna. Possibly one is 2D (XZ plane) distance and the other is 3D Euclidean, or stale state from a previous computation.

**Fix**: Both should show the same distance value, or label them differently (e.g., "3D distance" vs "ground distance").

---

### BUG-12: Peak S_ab displays "0.000 W/m^2" at low values

**Severity**: Medium (misleading)

At 30 dBm / 10.4 m, Peak S_ab is 4e-4 W/m^2 (visible in the legend) but the dashboard shows "Peak S_ab: 0.000 W/m^2" due to fixed 3-decimal formatting. Users might think the value is exactly zero.

**Fix**: Use scientific notation when values are below 0.001 W/m^2 (e.g., "4.0e-4 W/m^2").

---

### BUG-13: "Focus body" camera zooms too close or frames poorly

**Severity**: Low

The Focus body button produces a view where the body appears small at the bottom left of the viewport, with voxels filling most of the frame. Expected: body centered and filling most of the view.

**Fix**: Adjust the Focus body camera position/target to better frame the body mesh bounding box.

---

### BUG-14: No RT progress indicator or cancel button

**Severity**: Low (but high when RT hangs)

RT computation can take 30+ seconds or hang indefinitely (see BUG-9). The computing spinner shows but gives no sense of progress, estimated time, or way to cancel.

**Fix**: Add a progress bar or at least a "Computing RT... X seconds elapsed" counter. Add a cancel button that aborts the server-side computation.

---

### BUG-15: Paths dropdown missing "10 (multipath)" option

**Severity**: Low (inconsistency)

The features.md test groups reference 10 paths, but the dropdown only has 1, 5, and 20. Either add a 10-path option or update the docs.
