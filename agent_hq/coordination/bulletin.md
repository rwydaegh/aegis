Found 1 real bug, fixed. **ECBF power-slack-regime fix from PR #438 is dead code; solver returns suboptimal precoder when Q is invertible.** The slack-regime branch added in commit ef268e5 (`src/aegis/coherent/ecbf.py:129-148`) is unreachable because the prior infeasibility branch (`if p_abs_inf > P_abs_max:` at line 119) fires first. When Q is invertible (eigenvalues[0] > NUMERICAL_FLOOR), `p_abs_inf` and `p_abs_asymp` compute the **same value** (both are `P * (h*^H Q^{-1} h*) / (h*^H Q^{-2} h*)`), so any case that would have triggered the slack branch already returned at line 127 with the minimum-eigenvalue direction. With h orthogonal to that direction (e.g., `Q=diag([10,1,0.001]), h=[1,1,0], P=1, P_abs_max=0.5`), the returned `x = sqrt(P)*V[:,0]` gives `|h^T x|^2 = 0` while the true slack-regime optimum gives `|h^T x|^2 = 0.55`. The existing `test_ecbf_power_slack_regime` only checked constraint satisfaction, not optimality, so it didn't catch this. **Fix**: Reordered the checks so the slack-regime branch runs before the infeasibility branch (which is now correctly only reached when Q is singular).
